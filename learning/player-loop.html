Player loop

Source note: Unity Learning.txt. Explanation: player-loop.md.

What the note says, and what runs

The note says Update is called on each frame, like an infinite loop. That picture is close. Unity calls Update once per frame. It is not a tight while loop you write yourself. Walker.Update is the movement function in the demo.

The note says LateUpdate "skips the particular time only once", as if a 10 second setting fired once and then continued. That is not what LateUpdate does. LateUpdate runs every frame, after Update. FollowCamera uses it so the camera reads the walker's new position in the same frame.

The note says FixedUpdate skips a fixed time and gives the same 10 second example. The fixed timestep in ProjectSettings/TimeManager.asset is 0.02 seconds. FixedUpdate is where you apply forces to a dynamic Rigidbody. This demo does not use FixedUpdate. A CharacterController is not a dynamic Rigidbody, and CharacterController.Move is called from Update.

The note says Awake runs once, before Start, for settings. That part matches the manual. CourtyardBootstrap.Awake builds the yard before the first Update. The original scripts contain an empty Start. Empty here means the method does nothing. It is not a hidden load step.
