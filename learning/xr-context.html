XR context

Notes and the scene that stayed local

The learning note says an Oculus Rift has no processor of its own and uses the computer, and that Quest 2 is Android-based with its own battery and a store, and that Quest 3 has a stronger processor, more RAM, and better cameras than Quest 2. That is the workshop wording. It was not rechecked on a headset for this portfolio.

Two different scene files use similar names. vrscene.unity is 39,578 bytes, GUID 3e5932c951cc1e643bbb37dd13e56fd6. It names an inactive plane and camera, a light, an anchor, a teleportation anchor, and an XR Interaction Manager, and it instances the Starter Assets player, the Ely character, and the Ch08 character. The movement script on the Ely instance uses GUID 8da2fb2bc5e016b46a58a9a76e50a30f and is saved disabled.

VRScene-imported.unity is 3,541,156 bytes and a different GUID, bf8efc1ea90408840a27a268a2f11032. It is the city layout: terrain, vegetation, wall segments, gates, and 273 prefab GUIDs that belong to the Polylised Medieval Desert City folder. The same movement script text, under GUID acbb11b919ab48e4d949ae1887a16d60, is added to Ch15_nonPBR.fbx (115,014,208 bytes, not in this tree) and is also saved disabled. Starter Assets player prefabs are instanced. The XR Interaction Manager script is a package script, not a custom file.

Courtyard Walk does not load either scene. Copying the city file into Assets without the city prefabs, that character mesh, URP, and the XR package would show missing references. It would not become a playable city. The full account is workshop-evidence.
