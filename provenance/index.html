Provenance

The movement scripts, Unity Learning.txt, and the two scene files are workshop work. Courtyard Walk is the later scene that runs without those other files.

Workshop files in this tree

  • CharacterController.cs and NewMonoBehaviourScript.cs. The second file's script GUID is 8da2fb2bc5e016b46a58a9a76e50a30f.
  • Unity Learning.txt, unchanged. The learning pages correct it in separate text.
  • SampleScene.unity (7055 bytes, GUID 9fc0d4010bbf28b4594072e72b8655ab) and vrscene.unity (39578 bytes, GUID 3e5932c951cc1e643bbb37dd13e56fd6). Read what they reference before treating either as playable.

A separate template called My project has its own SampleScene of 11413 bytes. That is not the workshop scene and it is not merged into Courtyard Walk.

Referenced, not bundled into Courtyard Walk

  • Starter Assets. Its license.txt names the Unity Companion License. That names the license. It is not a conclusion that the package is cleared to post, and it is not a conclusion that it is barred.
  • The Ely character file credits K. Atienza. Ch08_nonPBR is a second character. No license file sat beside those meshes in the copy that was reviewed. vrscene instances both. The mesh bytes are not in this tree.
  • The notes name the Polylised Medieval Desert City on the Asset Store. That environment is not in SampleScene or vrscene, and it is not in Courtyard Walk.

Courtyard Walk does not load those files. Restoring vrscene means putting this scene file back next to the prefabs it already names, not stripping the prefabs and calling the scene fixed.

Corrections

The originals are not silently edited. The list of fixes is docs/corrections.md.
