# Unity files: required and regenerated

Open the folder that contains `Assets`, `Packages`, and `ProjectSettings`. Those three are required.

Required inside them:

- `Assets/Scenes/CourtyardWalk.unity` and its `.meta` (guid `4f8a1c2d6e7b49a0b3c5d6e7f8091a2b`).
- Every `.cs` under `Assets/Scripts/Courtyard` and `Assets/Editor`, each with the `.meta` that is already in the tree. Replacing a meta changes the script guid. The scene will lose `CourtyardBootstrap` if that one guid changes.
- Folder `.meta` files for `Scenes`, `Scripts`, `Scripts/Courtyard`, and `Editor`.
- `Packages/manifest.json`.
- `ProjectSettings/ProjectVersion.txt`, `ProjectSettings.asset`, `GraphicsSettings.asset`, `InputManager.asset`, `EditorBuildSettings.asset`, `TimeManager.asset`, and the other settings files in that folder. They hold the editor version, the input axes, the physics defaults, and the enabled scene.

Regenerated by the Editor, and omitted here:

- `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `obj/`.
- `packages-lock.json`.
- `Assembly-CSharp.csproj`, `workshop.sln`, and the other project files. The copies in the old tree were generated and included a Visual Studio analyzer path. They are not hand-written gameplay. Unity writes new ones on open. Leaving them out of this tree does not remove them from old commits.
- Baked lighting, a player build, and Burst output.

`CourtyardWalk.unity` does not embed the meshes. `CourtyardBootstrap` creates them on Play. The menu `Workshop/Build Courtyard Walk Scene` is optional and calls the same builder.

The demo does not reference Starter Assets, URP assets, XR settings, or the character meshes. Those can sit in a separate local archive and the courtyard still plays.
